# v0.1.2: less default generation context

Requested change: simplify the runtime for newer models by removing unnecessary
skills and context. The selected provider/model still passes through to its CLI.
This release does not change anyone's model selection or install a new CLI.

## What changed

- Keep the application contract once, in AGENTS.md or CLAUDE.md.
- Stop automatically loading the lesson corpus and separate edit skill.
- Link existing project notes instead of repeating their contents in the prompt.
- Keep engine guidance on demand. Remove its workspace capture section because
  the application performs browser verification outside the agent sandbox.
- Load the asset skill only for an approved positive budget; zero-budget jobs
  receive no optional skill definitions. Broker enforcement remains independent.
- Preserve the Pip, isolation, budget and Web-export contracts. Edits validate
  source and let the application perform the export.

Vendored Godogen source, attribution and original lesson files are preserved.
Old generated skill copies are archived outside discovery before migration.
See [generation](../guides/generation.md) for the restoration boundary. These
removals are scoped to the requested default-context simplification; unmeasured
skills are not being declared harmful or disabled globally.

## Paired pilot

Same task, Codex CLI 0.171.0, `gpt-6.2-astra`, CLI-default reasoning,
workspace-write sandbox, ignored user configuration, zero paid-asset budget.
One create and one color-only edit per arm, run sequentially on macOS arm64.
The lean arm is the no-optional-skill condition, retaining the application
contracts and an on-demand engine reference. Exact task text, source/skill
hashes, outcomes and token counters are in the
[evaluation receipt](runtime-context-20261124.json).

| Measure | v0.1.1 runtime | Lean runtime |
| --- | ---: | ---: |
| Create workspace instruction bytes | 46,801 | 9,021 |
| Optional skill definitions, zero budget | 2 | 0 |
| Create prompt bytes | 10,911 | 1,597 |
| Edit prompt bytes | 6,422 | 1,405 |
| Create + edit elapsed seconds, including export/verification | 197.83 | 133.40 |
| CLI-reported input tokens, including cached tokens | 432,509 | 248,975 |
| Of those, cached input tokens | 374,400 | 203,776 |
| CLI-reported output tokens | 4,544 | 3,463 |

Both arms passed source/artifact checks and trusted browser verification after
creation and editing. The final screenshots showed the requested magenta player,
three yellow stars and green Pip. A separate real keyboard driver completed
both games from score 0 to 3, with no remaining stars, terminal state true and
no page errors. This checks a small objective, not overall game quality.

The lean arm used about 81% less workspace instruction text, 42% fewer reported
input tokens and 33% less elapsed time in this pilot. There is only one paired
sample, no randomized ordering, and no broad model or task matrix. Cached-token
counts are not cost estimates. The normalized event stream showed no delegated
agent calls, but independent child-session accounting was unavailable: reported
tokens are CLI turn counters, **not certified whole-tree totals**. The receipt
marks whole-tree usage unavailable rather than inventing a total. These results
do not establish that an individual removed skill was harmful, or that newer
models always benefit from this change.

## Other checks and limits

The local backend suite passed 414 tests, including runtime contracts and real
broker-denial checks. Runtime tests cover both engine/provider combinations,
zero/positive budgets, historical-context archival and path isolation. The
upstream source hash check remains intact. Public CI also checks source hashes,
fresh installation, frontend build and worker-image construction.

Live Claude, Bevy, paid-asset generation, new provider login, mobile gameplay and
shared hosting were not evaluated here. The private development checkout and
global skills were not changed. The baseline harness and raw game/run evidence
are retained privately; generated assets and private event logs are not bundled
with this source release. Restore v0.1.1 to reproduce the old default context.
